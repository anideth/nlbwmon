# Установка экспериментального форка nlbwmon

[English](INSTALL.md) | **Русский**

> [!CAUTION]
> **Экспериментальная предварительная версия, не готовая для production.** Записи соединений могут теряться или содержать ошибки. Не используйте их для биллинга, нормативного контроля или аудита безопасности. Сохраните конфигурацию и базу учёта роутера; прежде чем устанавливать пакет на рабочее устройство, проверьте откат в лаборатории.

Форк заменяет **официальный пакет nlbwmon** экспериментальной сборкой. Обычный учёт трафика устройств сохраняется; добавляется необязательный экспорт JSONL-событий NEW/DESTROY. Сборщик Prometheus — отдельный компонент; приёмник событий реализован в Python-проекте [nlbwmon-aggregator](https://github.com/anideth/nlbwmon-aggregator).

## 1. Проверка совместимости и подготовка

Текущая схема сборки рассчитана на **OpenWrt 25.12.6** для **x86/64** (лаборатория) и **mediatek/filogic** (ARM64). APK для одной архитектуры или версии нельзя устанавливать на другую. Проверенного публичного бинарного prerelease пока нет.

Проверка роутера без изменений:

```sh
cat /etc/openwrt_release; apk list --installed nlbwmon; nlbw -c csv | head
```

Сохраните `/etc/config/nlbwmon`, базу учёта и сведения об установленном пакете. Для лабораторной VM лучше сделать snapshot, а для реального устройства иметь проверенный способ восстановления. **До** замены убедитесь, что исходный пакет доступен в репозиториях OpenWrt.

## 2. Сборка APK

На Linux x86-64 установите **SDK OpenWrt 25.12.6** (не ImageBuilder), соответствующий целевой архитектуре, с feed `packages` и `CONFIG_PACKAGE_nlbwmon=m`. Скрипт ожидает SDK в `~/projects/openwrt-sdk/` и чистую рабочую копию с зафиксированными коммитами в ветке `feature/flow-lifecycle-events`. Перед запуском просмотрите скрипт.

```sh
bash build-nlbwmon.sh --target x86-64
bash build-nlbwmon.sh --target filogic
```

Запускайте только команду для нужной платформы. Скрипт подготавливает исходники, настраивает рецепт SDK, добавляет **соответствующие форку UCI-конфигурацию и init-скрипт** и сохраняет APK, SHA256 и сведения о сборке в `~/projects/openwrt-packages/25.12.6/<target>/`. Сборка **не устанавливает** пакет на роутер.

Версия пакета форка — `0.1.0_alpha1-r1`, она отличается от версии upstream. Проверяйте **архитектуру, метаданные APK и SHA256**, а не только имя файла. Подробности: [сборка и откат](docs/BUILD_AND_ROLLBACK.md).

## 3. Сначала установка в лаборатории

Интерактивный скрипт деплоя предназначен для проверки; **полный цикл установки и отката пока не подтверждён испытаниями**. Скопируйте шаблон, укажите свои параметры локально и не добавляйте файл в Git:

```sh
cp deploy-nlbwmon.conf.example deploy-nlbwmon.local.conf && vim deploy-nlbwmon.local.conf
bash deploy-nlbwmon.sh
```

Выберите правильную платформу и сначала **Check only** (только проверка). Также есть **Deploy alpha** и **Roll back to official repository package**. Скрипт проверяет выпуск/архитектуру, создаёт локальную резервную копию и сверяет контрольную сумму переданного APK. **Автоматического отката при ошибке нет.** Резервная копия работающей базы не обязательно согласована.

После установки проверьте пакет, службу и обычный учёт:

```sh
apk list --installed nlbwmon; /etc/init.d/nlbwmon status; nlbw -c csv | head
```

Не заменяйте действующий `/etc/config/nlbwmon` целиком только ради секции экспорта. Проверьте соответствие установленных init-скрипта и конфигурации форку.

## 4. Необязательный экспорт соединений

Эталонный пример: [openwrt/files/nlbwmon.config](openwrt/files/nlbwmon.config). Изменяйте **существующий** файл командой `vim /etc/config/nlbwmon`. Не создавайте вторую секцию `flow_export`, если одна уже есть.

```uci
config flow_export
    option enabled '0'
    option router_name 'lab-router'
    option mark '0x40000000'
    option mark_mask '0x40000000'
    option max_flows '16384'
    option tcp_host ''
    option tcp_port ''
    option tcp_queue_size '1024'
    option tcp_reconnect_interval '5'
```

Это **пример с выключенным экспортом**, а не готовая политика для включения. Укажите адрес и порт действующего коллектора, затем включайте экспорт **только после подготовки приёмника**. Ненулевая `mark_mask` требует соответствующей политики маркировки conntrack: форк её не создаёт. Нулевая маска выбирает все значения и может резко увеличить объём событий. До изменения фильтра прочитайте [описание экспорта](docs/FLOW_EXPORT.md). Перезапускайте службу только после проверки конфигурации.

## 5. Установка принимающего коллектора

Для NEW/DESTROY в OpenSearch используйте **[INSTALL коллектора](https://github.com/anideth/nlbwmon-aggregator/blob/docs/bilingual-beta/INSTALL.ru.md)** ([English](https://github.com/anideth/nlbwmon-aggregator/blob/docs/bilingual-beta/INSTALL.md)) из соседнего проекта. **Этот репозиторий пока закрыт**, поэтому ссылки станут доступны остальным после публикации. Коллектор жизненного цикла обычно слушает **TCP 5517**; не путайте его со старым агрегатором Fluent Bit на **5515**. Перед настройкой `tcp_port` проверьте фактический порт приёмника.

TCP между роутером и коллектором **не шифруется, не аутентифицируется и не гарантирует доставку**. Используйте доверенную сеть с ограничениями firewall или защищённый туннель; не открывайте приёмник в Интернет. Перед использованием проверьте контролируемые события NEW/DESTROY в OpenSearch.

## 6. Откат и ограничения

Интерактивный скрипт может попытаться вернуть **официальный** пакет nlbwmon, но процедура понижения версии ещё не проверена. Храните исходный пакет и резервные копии. Сначала проверьте откат на лабораторной VM; не подменяйте рабочую базу старым снимком без необходимости.

Prometheus Lua collector **не входит** в APK. Его установка и особенности обновления прошивки: [Prometheus и резервирование](docs/PROMETHEUS_AND_BACKUP.md). Ограничения доставки и конфиденциальности: [limitations](docs/limitations.md).

**Условие публикации beta:** успешная чистая сборка, лабораторная установка, проверка NEW/DESTROY от роутера до OpenSearch, откат и аудит публикуемых данных.
