# nlbwmon: обзор проекта

[English](../en/OVERVIEW.md) | **Русский**

Экспериментальный форк [jow-/nlbwmon](https://github.com/jow-/nlbwmon) для OpenWrt. Он сохраняет обычный учёт трафика устройств и добавляет необязательный экспорт сведений об отдельных сетевых соединениях.

## Зачем понадобился форк

Нужно было одновременно решать две задачи:

- **Prometheus и Grafana:** сохранять привычную статистику трафика по устройствам. Для передачи метрик в Prometheus используется отдельный [nlbwmon Prometheus collector](https://github.com/giuliomagnifico/openwrt-nlbwmon-prometheus-collector), читающий данные nlbwmon.
- **OpenSearch:** собирать подробные события соединений — адреса, порты, протокол, время и объёмы переданных данных — для поиска и анализа.

Первоначальный подход с двумя независимыми сборщиками conntrack приводил к конфликту. Чтение счётчиков в режиме **«прочитать и обнулить»** (`GET_CTRZERO`) сбрасывает их в ядре. Если первый сборщик уже прочитал данные, второй может получить нули или только часть накопленного трафика. Из-за этого статистика расходится.

**Решение:** не запускать второй независимый опросчик со сбросом счётчиков, а добавить экспорт соединений непосредственно в nlbwmon и использовать его существующий путь получения данных.

## Как это работает

1. nlbwmon продолжает вести обычный учёт трафика устройств; сторонний Prometheus collector читает эту статистику для Grafana.
2. Встроенный экспортёр использует события Linux conntrack и тот же путь получения счётчиков, не создавая второго конкурирующего `GET_CTRZERO`-опросчика. Отбор соединений можно ограничить фильтром conntrack `mark/mask`.
3. Для соединений формируются JSONL-события `NEW` и `DESTROY`, которые отправляются по TCP на сервер приёмника.
4. Отдельный Python-проект [nlbwmon-aggregator](https://github.com/anideth/nlbwmon-aggregator) содержит коллектор жизненного цикла: он принимает события, сохраняет их в SQLite и передаёт обновления в OpenSearch. В проекте также есть отдельный legacy-агрегатор через Fluent Bit.

Экспорт соединений выключен по умолчанию и не требует второго демона на роутере. Формат событий: `nlbwmon-flow-v1`.

## Ограничения

- TCP-отправка не шифруется и не имеет прикладного подтверждения. При переполнении очереди, разрыве связи или потере событий ядра записи могут пропадать.
- Полнота данных зависит от conntrack, фильтра mark/mask и ёмкости таблицы потоков.
- Это не гарантированно полный журнал для биллинга, аудита или расследований.
- Не запускайте независимый второй опросчик `GET_CTRZERO` для тех же счётчиков.

## Перед установкой

Проверьте соответствие APK версии OpenWrt и архитектуре устройства. Сохраните конфигурацию и базу учёта. Установку и откат сначала проверяйте в лаборатории.
